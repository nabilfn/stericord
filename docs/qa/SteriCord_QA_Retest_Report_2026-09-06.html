4. Detailed Evidence and Observations

4.1 D-01 — Equipment audit coverage

A synthetic equipment record was created, moved to MAINTENANCE and edited. Audit inspection returned exactly EQUIPMENT_CREATED, EQUIPMENT_STATUS_CHANGED and EQUIPMENT_UPDATED in order. The equipment trigger performs server-side logging, and audit-chain verification remained intact.

4.2 D-02 — Quarantine atomicity

A synthetic pack was moved to PENDING_VERIFICATION and quarantined as a supervisor. Exactly one public.quarantines row was created. A second quarantine attempt was rejected and the row count remained one. Both PACK_QUARANTINED and QUARANTINE_STARTED events referenced the same pack.

4.3 D-03 — Incident lifecycle auditing

The incident advanced ALERTED → ACKNOWLEDGED → REPLACEMENT_DISPATCHED → RESOLVED → CLOSED. The resulting sequence was INCIDENT_ACKNOWLEDGED, INCIDENT_REPLACEMENT_DISPATCHED, INCIDENT_RESOLVED and INCIDENT_CLOSED. Empty resolution notes, nurse acknowledgement and terminal regression were rejected.

4.4 D-04 — Offline OT queue

Static inspection found encrypted payload storage, a secure-storage encryption key, persistent queue states, stable client operation IDs, server-side idempotency, recovery of SYNCING records and capped exponential delay. Authentication changes also preserve a cached authenticated profile during transport failures.

This does not prove physical-device acceptance. The original scenario must still be repeated with radios disabled while an eligible pack is open.

4.5 D-05/D-06 — Reporting

The freshly rebuilt reporting service denied OT_NURSE and CSSD_TECHNICIAN report exports with 403, allowed HOSPITAL_ADMIN and CSSD_SUPERVISOR equipment exports, produced a valid PDF, denied Hospital B access to Hospital A equipment with 404, and created no success export row for blocked nurse attempts. Empty, whitespace-only, missing and garbage bearer credentials all returned 401.

4.6 D-07/D-08 — Deactivation

An active user's session succeeded before deactivation. After profiles.is_active was set false, role-gated access returned no protected equipment. Password login and refresh using a pre-existing refresh token both returned HTTP 403, issued no token, used the stable “Account is deactivated” message and did not expose SQLSTATE P0001. Wrong-password behavior remained 400, another active user remained unaffected, and the reactivated user immediately returned to HTTP 200 login.
